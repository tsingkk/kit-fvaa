# Kit 文件存档助手 (Kit File Version and Archive Assistant)

**Kit 文件存档助手** 是一个基于 Python 开发的轻量级、图形化本地文件版本管理工具。它可以帮助用户针对指定目录中的文件进行存档、版本控制、忽略监视和历史回溯。适合非程序员、写作者、设计师、以及需要频繁修改文件的场景使用。

## ✨ 主要功能

- **📦 存档**: 快速将工作目录中的当前状态保存为一个版本，自动排除临时文件和无用目录（如 `.git`, `node_modules`, `__pycache__` 等）及忽视文件列表中的文件及目录。
- **🌿 分支管理**: 类似 Git 的分支体验。默认分支为 `main`；可以当前状态为基线创建新分支，每个分支拥有独立的版本号序列（从 1 开始）；支持在分支间自由切换，切换时工作目录自动恢复为该分支的最新归档；提供“分支历史”图谱，以类 Git 分支图直观展示各分支的版本演进与分叉关系。
- **🕒 版本历史与日志**: 
  - 版本号在分支内自动递增，不同分支互不干扰。
  - 支持为版本添加 **Markdown格式** 的修改说明和自定义标签。
  - 清晰显示每次存档的时间和备注，随时查看历史操作记录。
- **⏪ 文件回溯**: 轻松选中历史版本，一键安全恢复，将工作目录还原到指定状态。
- **📤 取回指定文件**: 在版本历史中点击“文件清单”列的“点击查看”，弹窗展示该归档的文件列表，勾选单个或多个文件即可复制回当前工作目录（自动重命名，归档内原文件保持不变）。
- **👀 状态监视**: 在图形界面中高亮显示工作目录各文件的实时状态（**新增**、**修改**、**删除**、**不变**）。支持手动刷新和后台自动监视。
- **🚫 忽视文件规则**: 类似 Git 的 `.gitignore`，可自定义需要忽略的文件或目录，避免存档不必要文件，支持通配符。
- **💾 存储空间优化**: 使用 **硬链接 (Hard Links)** 技术处理不同版本中未发生改变的文件。无论你存了多少个版本，只要文件没变，就不会造成额外的硬盘空间开销。
- **📁 格式通用**: 适用于绝大多数文件类型，无论是文本代码还是图片、音频等二进制文件，均可存档。
- **🎨 现代图形界面**: 采用简约的暗黑风格界面 (Cyborg 主题)，定制滚动条和高亮提示，对比度适宜，操作直观。

## 🛠️ 技术栈

- **语言**: Python 3.x
- **GUI 框架**: `tkinter`, `ttkbootstrap`
- **文本渲染**: `markdown`, `tkhtmlview`
- **核心逻辑**: `hashlib` (MD5比对), `os.link` (硬链接优化)

## 🚀 安装与运行

你可以通过以下两种方式之一运行本程序：

### 方式一：直接运行可执行文件（推荐 Windows 用户）

无需安装 Python 环境，直接下载单文件可执行程序即可运行，目前最新版本为 v1.2：
1. 从仓库 `release` 下载最新版本的 `kit-fvaa-v1.2.exe`，存放至指定目录中；
2. 双击运行即可。

**注意**：程序运行后会在同一目录下生成`fvaa_config.json`文件，此为程序所需文件，需保留。

### 方式二：从源码运行

1. **克隆本仓库或下载源码**:
   ```bash
   git clone https://github.com/yourusername/kit-fvaa.git
   cd kit-fvaa
   ```

2. **安装 [uv](https://docs.astral.sh/uv/)**（尚未安装时）：
   ```powershell
   winget install astral-sh.uv
   ```
   无需手动安装 Python：uv 会在需要时自动下载项目要求的解释器（>=3.12）。

3. **安装依赖**（依据 `pyproject.toml` 与 `uv.lock` 自动创建 `.venv` 虚拟环境并安装依赖）：
   ```bash
   uv sync
   ```

4. **运行程序**:
   ```bash
   uv run python main.py
   ```

## 🧱 构建单文件 EXE（Windows）

无需安装 Python 的目标机器可直接运行构建产物。项目使用 [Nuitka](https://nuitka.net/) 将程序编译为单一 EXE（含 Python 运行时与全部依赖）。

**前置条件**（二者其一）：
- MSVC C 编译器：`winget install Microsoft.VisualStudio.2022.BuildTools` 并勾选 “使用 C++ 的桌面开发” 工作负载；
- 或 MinGW-w64 gcc。

另需 [uv](https://docs.astral.sh/uv/)（`winget install astral-sh.uv`）管理构建环境。

**构建**（自动执行 `uv sync` → 清理 `dist/` → 编译）：

```powershell
# 默认构建 standalone（目录版，先验证）+ onefile（单文件版）
pwsh -File scripts\build_windows_onefile.ps1

# 仅构建单文件版，并在完成后自动启动做冒烟验证
pwsh -File scripts\build_windows_onefile.ps1 -Mode onefile -Verify

# 仅构建 standalone 目录版（调试首选，启动快、可直接查看 dist\main.dist 内容）
pwsh -File scripts\build_windows_onefile.ps1 -Mode standalone
```

**产物**：
- `dist\kit-fvaa.exe` — 单文件版（onefile，约 16.6 MB，zstd 压缩）。首次启动需解压，有 1–2 秒延迟属正常现象；
- `dist\main.dist\kit-fvaa.exe` — standalone 目录版（约 60 MB），用于排查问题；
- `dist\nuitka-report-*.xml` — 编译报告，可用于核对打包内容。

**运行注意**：与源码模式一致，程序启动后会在 EXE 同目录生成/读写 `fvaa_config.json`，请保留该文件。

**清理**：直接删除 `dist/` 目录即可（构建脚本每次也会先自动清理）；所有构建产物均已加入 `.gitignore`。

**常见问题**：
- 报错 “No C compiler found” → 按上方前置条件安装编译器后重试；
- 杀毒软件误报/隔离 EXE → Nuitka 编译产物偶被启发式误判，可将文件加入白名单；
- 重复构建缓慢 → 首次全量编译较慢，之后命中 clcache 缓存通常只需数十秒。

## 📖 使用指南

1. **选择工作目录**: 
   - 点击“选择目录”按钮，指定你需要进行版本管理的本地文件夹。
   - **历史记录**: 软件会自动记住最近打开过的 5 个目录，你可以直接通过下拉列表快速切换。
2. **状态刷新与监视**: 
   - **自动监视**: 选择目录后，软件会自动开启后台监视，并根据文件变动实时刷新状态。
   - **手动控制**: 你可以点击“停止监视”来暂停自动更新，或点击“开始监视”重新开启；点击“刷新状态”可随时手动触发一次全量比对。
   - **忽视文件**: 点击“忽视文件”按钮，可以设置不需要存档和监视的文件规则（支持 `*.log` 等通配符，配置保存在 `.fvaa/.fvaaignore` 中）。
3. **编辑说明与存档**: 
   - 点击“编辑存档说明”，可以使用 Markdown 编写本次存档的详细日志。
   - 弹窗上方为只读的**文件状态清单**（**删除**、**新增**、**修改**，每次打开自动更新、不可修改），存档时将自动附加到存档说明顶部随版本一并保存，方便后期查阅；存档说明在弹窗下方输入。
   - 点击“存档”会先弹出“编辑存档说明”窗口，弹窗分为三栏：上方只读显示文件状态清单（当前无变更时显示占位提示），中间输入存档说明，下方填写本次存档的标签（存档时自动关联到该版本，留空则不添加；标签在同一分支内不可重复，与已有标签重名时无法保存）；点击弹窗中的“保存”后才会执行存档，说明内容为空时无法存档，可点击“放弃”或关闭窗口取消本次存档。存档文件会安全地存放在工作目录下的 `.fvaa` 隐藏文件夹中。
4. **版本管理与回溯**:
   - 在右侧“版本历史”面板中，可以查看**当前分支**的所有存档版本。
   - **添加标签**: 存档时在弹窗的标签输入框中填写标签（如 `Release v1.0`），存档后自动关联到该版本；也可点击“版本历史”表中无标签版本“标签”列的“添加标签”，单元格原位变为输入框，输入标签后按回车确认即可打上标记（按 Esc 或点击其他位置取消）；已有标签的版本则直接显示标签内容。
   - **查看说明**: 点击版本列表中的“说明”列，可弹窗查看渲染后的 Markdown 文档。
   - **取回指定文件**: 点击版本列表中的“文件清单”列（每行均显示“点击查看”），弹窗展示该归档中的文件列表（含文件大小）；勾选一个或多个文件后点击“取回”，文件将被复制到当前工作目录并自动重命名为 `原文件名-分支名称-版本名称-归档日期`（连接符为“-”；有标签时版本名称为 `版本号-标签`，无标签时为 `版本号`；与现有文件重名时自动追加序号；子目录中的文件会平铺到工作目录根下），归档中的原文件不会被重命名或修改。
   - **恢复版本**: 选中需要恢复的历史版本，点击“恢复版本”即可将工作目录一键还原到该版本状态。
5. **分支管理**:
   - **创建分支**: 点击“创建分支”按钮，以当前分支最新归档为基线创建新分支（新分支版本号从 1 开始独立递增），创建后自动切换到新分支。
   - **切换分支**: 点击“切换分支”按钮，弹窗中会列出各分支名称及最后归档时间；选择目标分支后，界面信息切换至对应分支，工作目录文件恢复为该分支最新归档。
    - **分支历史**: 点击“切换分支”右侧的“分支历史”按钮，弹窗以类 Git 分支图的形式展示所有分支的版本图谱：每列代表一个分支，归档版本按存档时间排列（较新版本在上、较早版本在下）；连线严格按版本继承关系绘制——正常顺序存档的版本与前一版本以直线相连，恢复旧版本后存档的版本以同列弧线连回被恢复的版本，分支的首个存档版本以跨列曲线连回其来源分支的基线版本（空心节点为尚未归档的分支创建点）；当前分支高亮显示，点击任意版本节点可查看该版本的时间、标签及 Markdown 渲染的存档说明。
   - **前提条件**: 创建或切换分支前，当前目录必须已完成归档且无变更文件，否则会弹窗提示“先归档当前目录”。
   - 界面第 4 行正中间会始终显示当前所在分支名称；“版本历史”和“操作历史”面板也仅展示当前分支的内容。
6. **操作历史**: 
   - 左侧面板会记录当前分支的每一次存档、恢复及分支操作（创建/切换分支），点击相应的历史记录可以快速回顾过去的操作流程。
   - 存档记录以绿色高亮，恢复记录以棕色高亮，分支操作以蓝色高亮，方便区分。

## 🧠 工作原理与文件结构

- **差异比对**: 核心类 `VersionControl` 会遍历目录并计算文件的 MD5 哈希值，结合文件修改时间精准判断文件变更状态。对于设为“忽视”的文件夹，程序将直接跳过遍历，保障检索速度。
- **本地存储机制**: 所有的版本数据及配置全部集中保存在工作目录下的 `.fvaa/` 隐藏文件夹中，按需生成，不会污染系统的其他地方。
  - `.fvaa/versions/<分支名>/<版本号>/`: 按分支和版本号分别存储不同时期的文件副本（旧版本数据会自动迁移为 `main` 分支）。
  - `.fvaa/manifest.json`: 存储分支结构、各分支版本元数据、标签映射表以及完整的操作历史日志（每条记录带分支标记）。
  - `.fvaa/cache.json`: 当前工作区文件的状态缓存，用于快速对比。
  - `.fvaa/.fvaaignore`: 用户自定义的忽视文件配置列表。
- **分支机制**: 每个分支在 `manifest.json` 中拥有独立的版本序列和标签表；新分支创建时会记录基线快照（来源分支的对应版本），因此尚未归档的新分支也能正确切换与恢复。版本号仅在分支内部递增，互不干扰。
- **硬链接优化策略**: 每次新建存档时，如果文件与同一分支内的上一个版本相比 MD5 相同（即未发生变化），系统会优先使用操作系统底层的 `os.link` 为文件创建硬链接，直接指向上一版本的文件位置。这避免了重复拷贝，极大提高了运行效率并节约了磁盘空间。
